## J1 窗口尺寸类与自适应导航

- 新增纯 Kotlin `presentation/adaptive/WindowLayoutPolicy.kt`：`WindowWidth`（Compact <600dp /
  Medium 600–839dp / Expanded ≥840dp，与 Material 3 断点一致）、导航形态、正文/工作区宽度、
  页面边距、Feed 列数、首页双栏、设置 list-detail、折痕内容收敛与 list-detail 主栏宽度。
- `MainActivity` 用官方 `calculateWindowSizeClass(activity)`（`material3-window-size-class`）取尺寸类，
  通过 `LocalWindowWidth` 注入全应用；不再有第二处 `LocalConfiguration.screenWidthDp` 判断。
  四个一级入口按 `NavigationLayout` 选择：Compact 底部 Navigation Bar，Medium/Expanded Navigation Rail。
  抽屉规则留在策略层（≥7 个入口才建议 Drawer），当前四个入口按密度选择 Rail，不引入抽屉。
- 保留原有 testTag（`tab-bar`、`tab-*`、`navigation-rail`、`rail-tab-*`）、IME 隐藏、下载结果徽标、
  edge-to-edge 与安全区行为；`navigation-rail` 宽度收敛到 `AppSpacing.navigationRailWidth`。
- 设备证据：`compactWindowKeepsBottomBarAndFullWidthTabs`（底栏存在、Rail 不存在、底栏入口 ≥48dp）、
  `mediumWindowSwitchesToRailAndKeepsCurrentPageWhenResizingBack`（700dp 出 Rail，点「已存」后缩回
  480dp 仍是已存页——窗口尺寸变化不重建、不丢页面状态）。截图：
  `compact-480-home`、`medium-700-home`、`medium-700-library`、`expanded-1200-home`、
  `landscape-expanded-home`（真实横屏 952dp）。

## J2 各页面 canonical layout 与折叠姿态

- `AdaptivePage` 拆成两档内容宽度：`READABLE` 840dp（首页、任务页、结果页）与 `WORKSPACE`
  1040dp（已存，仅 Expanded 放宽）；`AdaptiveWorkspacePage` 是已存入口。
- 首页 Expanded 双栏：左「解析主面板 + 首次引导」，右「站点专区 + 最近保存」；`testTag`、业务
  流程与渐进披露不变。设备用例 `expandedWindowSplitsHomeIntoTwoPanes` 断言站点卡片位于解析面板右侧。
- 已存 Feed 列数 Compact/Medium/Expanded = 2/3/4；任务页保持可读单列（未加宽）。
  `LibraryFeedColumnsDeviceTest#feedColumnsFollowWindowSizeClass` 用真实的
  `LazyVerticalStaggeredGrid` 几何断言行内项数 2 → 3 → 4；`expanded-1200-library` 为真实 1200dp
  截图（4 列），`medium-700-library` 为真实 700dp 截图（3 列）。
- 设置 Expanded 改为 list-detail：左侧分类列表常驻，右侧详情默认「外观与语言」，子页不再显示返回键；
  Compact/Medium 保持单栏 + 返回键。设备用例
  `expandedSettingsUsesListDetailInsteadOfSubpageNavigation`。
- 折叠姿态：`rememberFoldFeature` 用 `WindowInfoTracker` 收集 `FoldingFeature`，`foldPane` 取折痕一侧
  （book 取较宽半屏、tabletop 取较高半屏），`AdaptivePage` 同时收敛宽度与高度。JVM 覆盖
  无折痕 / 不可分离 / 左右半屏 / 上下半屏 / 退化边界共 5 例。

## J3 设计 Token 收敛

- 页面边距统一由 `pagePadding()`（Compact 16dp / Medium+ 24dp）给出，替换首页、任务、已存、设置
  的 22dp；`AppSpacing` 增加 `pageHorizontal`、`navigationRailWidth`，新增 `AppShapes` 圆角阶梯，
  `Theme` 与浏览器底部面板共用同一组数值。
- 私有 `RoundedCornerShape` 收敛：浏览器面板（顶部大圆角 + 条形容器）、看图器（12dp/10dp）、
  播放器控制层（10dp）、应用图标（18dp）分别映射到 `MaterialTheme.shapes` / `AppShapes`。
- 新增 `theme/BrandColors.kt`：站点徽标紫蓝渐变、品牌图标渐变、封面选择圈暖橙与对勾色集中到这里；
  首页/站点/图标/已存不再散落十六进制颜色。普通选择态、描边与容器继续走 `colorScheme`，
  `dynamic-dark-home` 显示 Material You 调色板确实替换了暖橙（站点徽标作为品牌例外保留紫蓝）。
- 组件固有尺寸（图标 18/20/22dp、8dp 行内间隔等）保留原值，不做无意义迁移。

## J4 视觉层级与组件语义

- 首页解析区去掉外层描边，只保留单一 `surfaceContainerLow` 工作区，输入区用一档 `surfaceContainer`
  建立 tonal 层级；卡片内边距改 `AppSpacing.md`。
- 底部导航与侧边导航容器由 `surfaceContainerLowest` 改为 `surfaceContainer`，与正文形成 tonal 分隔。
- 已存多选工具条改成 contextual toolbar：`surfaceContainerHigh` 底 + 原有三个动作与全选语义，
  不改变批量操作流程。
- `BatchImportDialog` 的宽版判断也从 `LocalConfiguration.screenWidthDp >= 600` 换成同一个
  `LocalWindowWidth`，`P2BatchImportDeviceTest` 10/10 复跑通过。
- 任务搜索评估结论：当前 M3 版本的 `SearchBar` 激活后全屏展开并接管 IME/返回，会改变本页
  「搜索框常驻 + 筛选 chip 同行」的既有流程与 `task-search` 断言，故保留 `OutlinedTextField`
  （形状沿用 `shapes.large`），本轮不套用 SearchBar。

## J5 无障碍与动效补齐

- 四个主页面标题（`TabPageHeader`）与设置子页标题补 `heading()` 语义；设备用例
  `pageTitlesCarryHeadingSemantics` 断言「拾影」「下载任务」带 Heading。
- 已存封面选择圈：去掉误用的 `stateDescription = 标题`，改为 `contentDescription = 标题`，
  选中状态由 `Role.Checkbox` 自行朗读；底栏入口触控高度在设备上断言 ≥48dp。
- 扩写 `ThemeContrastTest`（保留原有品牌色固定断言）：亮/暗两套品牌主题按 WCAG 相对亮度计算，正文 ≥4.5:1（onBackground /
  onSurface / onSurfaceVariant 对两个 surface 容器 / onPrimary / onSecondaryContainer /
  onTertiaryContainer / onError / onErrorContainer / inverseOnSurface），重要边界 ≥3:1
  （outline 与 primary 对 background）。
- 动效：继续沿用 `appMotion()` 与系统动画缩放（缩放为 0 时不启用位移/缩放）；本轮没有替换
  `MotionScheme`/spring——当前 Compose BOM 下的替换会改变设备测试 idle 与共享元素回程时机，
  留待单独评估。

## 顺带修复的既有陈旧用例

`Material3NavigationDeviceTest`、`DynamicColorDeviceTest`、`AppearanceModeDeviceTest` 仍按设置页
「单页平铺」编写（点「我的」后直接找「外观模式 / 默认画质 / 动态取色」），而 `641ed78` 已把设置改成
分类列表 → 子页。本轮按现信息架构补一次「外观与语言 / 下载与网络」点击，断言意图不变；修好后
分别为 3/3、1/1、1/1 通过。另把 `AppearanceModeDeviceTest` 的系统栏 flag 与背景亮度断言改为
轮询到稳定再断言（主题切换后系统栏与窗口重绘是异步的），连续「Material3Navigation → DynamicColor
→ AppearanceMode」三连跑不再因顺序抖动失败。`DownloadCenterSettingsDeviceTest` 的 1200dp Rail 用例原先
用 `LocalConfiguration` 注入宽屏，现改为注入 `LocalWindowWidth`（与 `calculateWindowSizeClass` 等价）；
其「更多任务操作」断言改为「至少一个」——设备上已有其它任务时不再因为全局唯一而误报，改后 6/6 通过。

## 未覆盖边界

- **真实分屏**：该 AVD（Pixel 10 Pro / API 37）的 Recents 长按菜单不提供分屏入口，`am start
  --windowingMode 3/4` 也无法让两个任务同时可见；已用 `wm size` 的真实窗口尺寸变化与 freeform
  真实小窗覆盖，但**未在真实分屏下验证**，不得以相邻结果替代。
- **折叠屏 tabletop/book 铰链姿态**：本机没有折叠屏设备，也没有可用的 device state；
  `foldPane` 只有 JVM 几何用例，未在真实折痕上验证。
- **Material You 对比度**：动态调色板由系统生成，无法在 JVM 构造；截图只做人工观感核对，
  未做逐像素对比度断言。
- **TalkBack 全链路**：只做了启用后的首页/设置观感与 heading 语义断言，未跑通 TalkBack 手势逐项走查。
- 平板（≥600dp 的大屏真机）未验证；480/700/1200dp 全部在模拟器上完成。
- 组件固有 dp（图标尺寸、徽标 3/5/6/7dp 内边距、拖拽把手命中区）仍是原值，未做穷举迁移。
