# 下载自动继续验证（2026-10-09）

## 实现

- 新增可关闭的自动继续策略，默认开启：「我的 → 自动继续下载」。
- 记录暂停原因 `DownloadPauseCause`（USER / NETWORK / PROCESS），随下载历史持久化；旧历史缺少该字段时按用户暂停处理，升级后不会自动复活用户主动停下的任务。
- 只有 `canAutoResume` 为真的任务会被自动继续：暂停且原因为网络/进程中断，或失败类型为 NETWORK、STORAGE_FULL。登录、访问受限、链接过期、限流、后台服务、引擎及不支持等失败仍由用户决定。
- 触发时机：网络恢复（网络策略 `allowed` 变为可用）、用户打开自动继续开关、进程启动恢复后立即执行一次，以及仅在自动继续开启时的周期扫描（默认 15 秒），用于发现磁盘空间释放。
- 阻塞条件仍在时只等待、不计次：网络不可用或空间不足的任务会被跳过，不消耗重试预算。
- 自动重试有次数上限（默认 3 次，`AutoResumeBudget`）。任务在尝试期间（PENDING/RUNNING）保留预算，只有完成、取消、用户暂停或变为不可自动继续的失败才释放；网络恢复或开关开启视为条件变化，重新获得预算。
- 主动暂停的任务永不自动继续；关闭开关后所有中断都需手动点击继续。Wi-Fi 暂停提示同步改为中性描述。

## 验证

执行：`:app:testDebugUnitTest`（完整 JVM 套件）、`:app:compileDebugAndroidTestKotlin`、`:app:assembleDebug`。

- 238 项 JVM 测试通过，0 失败、0 错误、0 跳过；其中本功能新增 18 项：
  - `AutoResumePolicyTest`（5 项）：网络/进程暂停可自动继续，用户暂停与旧历史不可；仅 NETWORK、STORAGE_FULL 失败可自动继续，其余失败与活动/完成任务不可。
  - `AutoResumeBudgetTest`（6 项）：到达上限后停止、非候选任务释放预算、条件变化重置预算、尝试期间保留预算、仅 PENDING/RUNNING/仍可自动继续的任务保留预算、非法上限被拒绝。
  - `AutoResumeDownloadTest`（7 项）：网络恢复后无点击自动完成；NETWORK 失败任务按已保存偏移 `bytes=4096-` 续传而非从零开始；用户暂停在网络恢复后保持暂停且断点字节不变；关闭开关时等待、打开后继续；进程退出遗留任务在下次启动自动完成；旧历史无暂停原因时保持手动且不发起请求；磁盘写满时等待、释放空间后自动完成。
- 本地 HTTP 测试服务器覆盖真实计数器与 Range 头，网络策略和可用空间为可控注入，扫描间隔缩短到 40 ms。
- Debug 应用与 Android 测试源码编译成功。

## 验证边界

- 未做真机验收：真实 Wi-Fi 断开/恢复、真实移动网络切换、真实磁盘写满后释放空间，以及 Android 15 前台服务时限下的自动继续，均需在设备上补充端到端验证。JVM 测试使用注入的网络策略与空间计数器，不能替代真实系统行为。
- 实体设备侧新增的偏好持久化断言位于 `DownloadSettingsDeviceTest.autoResumeDefaultsToOnAndPersistsBothChoices`，本次未在设备上执行。
- 未改变后台下载服务、通知与 Android 15 系统时限的既有行为；自动继续只负责重新排队。
- 自动继续不会处理登录失效、链接过期、限流等需要用户介入的失败，也不绕过仅 Wi-Fi 设置。
