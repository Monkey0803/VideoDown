## 设计取舍

- **手势只在系统播放控件隐藏时接管。** PlayerView 自带的进度条 / 播放键 / 全屏键就占着同一块区域，覆盖层常驻会把这些按钮全部挡住。隐藏时覆盖层接管触摸，**单击**用于把控件唤回来，行为与原来一致。
- **手势层是兄弟覆盖层，不是父节点。** AndroidView 自己会消费 `down`，挂在父节点上的手势检测器永远等不到未消费的按下事件（实测如此）。
- **长按加速用独立指针节点。** `detectTapGestures` 的 `onPress` 在长按**开始**时就释放，拿不到真正的抬指时刻；因此长按由 `detectTapGestures(onLongPress)` 触发加速，另用一个节点等待抬起并结束加速。
- **竖直拖动与点击分属两个指针节点，拖动放在最后。** 主通道里内层节点先看到位移，才能让一次滑动成为拖动而不是点击。
- **离开播放页把屏幕亮度交还系统**，不把播放页的临时亮度带到其它页面。
- **限速用共享令牌桶。** 一个实例服务所有直链传输，所以全局上限约束的是**总量**而不是"每个任务的默认值"；每个任务另有自己的桶，两者每次写入都要通过。限额放在**空间检查之后**，磁盘写满仍然立即失败而不是先睡一觉。
- **自动入库移出传输协程。** 完成回调原本同步阻塞在引擎释放队列名额之前，现在相册拷贝在应用作用域执行，完成通知在拷贝之后发出，于是**一张卡**同时回答"下好了"和"存哪了"。
- **继续观看必须核对文件身份。** 只比 record id 会在重新下载或转码后显示旧进度条，把人带错位置，因此要求 size 与 mtime 都一致。
- **睡眠定时保存绝对时刻**，服务每 2 秒比对一次，因此关掉播放页计时仍在走；到点执行**暂停**（可恢复）而不是停止。

### 逐项证据（含实测数字）

- **B1a 手势**（`PlayerGestureDeviceTest`，两台设备均通过）：真实播放器上注入触摸，左右半屏双击分别显示 `+10 秒` / `-10 秒`；右半屏上滑后**系统媒体音量确实上升**（模拟器 3 → 5，max=15；真机 5 → 9，max=25），左半屏上滑后**窗口亮度从 -1.0（跟随系统）变为手势值**（模拟器 0.55；真机 1.0）；长按期间显示 `2× 快进中`，抬指后标签消失。证据：`evidence/emulator-player-gesture-evidence-summary.txt`、`evidence/device-player-gesture-evidence-summary.txt`。
- **B1b 字幕**（`SubtitleSidecarDeviceTest`，两台设备均通过）：写入同名 `.srt` 后 20 秒内出现「字幕」开关，关闭后偏好为 `false`、标签变「字幕 关」，再开启后偏好为 `true`；**没有字幕文件时不出现该开关**（证明轨道探测不是恒真）。证据：`evidence/*-subtitle-evidence-summary.txt`。
- **B2 限速**（`SpeedLimitDeviceTest`，两台设备均通过）：
  - 同一 10542 字节文件，`不限速` vs `全局 8 KB/s`：模拟器 23ms → 305ms，真机 66ms → 346ms，两次下载字节完全一致；
  - 排队中的任务先设 `8 KB/s` 再放行：模拟器 330ms、真机 360ms 完成且字节一致（10 KB 在 8 KB/s 下不可能快于 287 ms，这是速率本身的下限，不是机器速度测量）；
  - 任务卡设置 `5 MB/s` → 记录持久化为 `5120`、卡片与操作项都显示「限速 5 MB/s」→ 改回「跟随全局」后归零。
  - JVM 用虚拟时间断言节流节奏：1 KB 恰好消耗 1 虚拟秒、提高速率后等待缩短、空闲不囤积分、时钟回退不产生额度。证据：`evidence/*-speed-limit-evidence-summary.txt`、`evidence/*-speed-limit-evidence-queued-task.txt`。
- **B3 自动入库**（`AutoGalleryDeviceTest`，两台设备均通过）：真实下载完成后 MediaStore 出现条目（`content://media/external/video/media/75`），**读取该条目的 SHA-256 与本地文件一致**，完成通知全文包含「已存入相册」。证据：`evidence/*-auto-gallery-evidence-summary.txt`、`evidence/*-gallery-card.png`。
- **B4 继续观看**（`WatchProgressDeviceTest`，两台设备均通过）：写入与文件匹配的进度后出现进度条与「已看 25%」，新实例读取同一偏好文件也能看到；改为已播完或改为与文件大小不一致的陈旧进度后，进度条与百分比都消失（响应式，无需重进页面）。
- **B5 睡眠定时**（`SleepTimerDeviceTest`，两台设备均通过）：对话框选择 15 分钟写入的 deadline 落在 14–16 分钟区间并显示剩余时间；把 deadline 设为 +3 秒后**真实音频播放被暂停**且 deadline 被清零（无法二次触发）。证据：`evidence/*-sleep-timer-evidence-summary.txt`。

## 未通过项与未覆盖边界

- **`P3PictureInPictureDeviceTest#pipScreenOffThenReturnKeepsActivityAndPlayer` 在 API 37 模拟器上失败，与本轮无关。** 该用例操作真实熄屏与 PiP。两种独立实验都表明不是本轮引入：把 `PlayerScreen.kt` 整体还原到 HEAD 后同样失败；只关闭新增的手势覆盖层后同样失败。未修改该用例，记为模拟器环境限制。
- **手势只在系统控件隐藏时生效**（设计取舍）。控件显示时双击/滑动不做任何事。
- **手势区域未在平板/折叠屏验证**，只在手机竖屏与既有横屏用例上验证。
- **长按加速只改变当前播放速度**，不写入倍速偏好；松手恢复到用户设置的倍速。
- **分片引擎下载（yt-dlp / FFmpeg）不受限速影响** —— 它们是独立进程，无法按字节节流。设置页文案已说明。
- **单任务限速不提供"该任务不限速"**，只有「跟随全局」与具体速率，否则会在全局上限上开一个洞。
- **未测量多任务并发时的总量精度**：全局上限的共享桶由 JVM 虚拟时间用例覆盖，设备上只量到单任务真实时长。
- **字幕只验证轨道存在与开关行为**，没有逐像素断言字幕文本真的绘制在画面上。
- **字幕只支持与视频同名的 sidecar**，不做字幕下载（`docs/TODO.md` 的 C2）。
- **睡眠定时到点执行暂停**而非停止或退出；只对音频提供。
- **自动入库在 Android 9 及以下需要预先授予存储权限**，未授权时不复制、只在通知里说明原因，不弹权限请求（后台完成无法弹窗）。
- 亮度手势的起点在系统未覆盖亮度时取系统值；播放页退出后恢复"跟随系统"，不保留用户在手势里调出的亮度。

## 复现命令

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"

./gradlew testDebugUnitTest                 # 324 用例
./gradlew :app:installDebug :app:installDebugAndroidTest
adb shell cmd appops set com.videodown.douyin.debug POST_NOTIFICATION allow   # 通知相关用例前提
./gradlew connectedDebugAndroidTest \
  -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true \
  -Pandroid.testInstrumentationRunnerArguments.class=com.videodown.douyin.SpeedLimitDeviceTest
```

> `-Pandroid.testInstrumentationRunnerArguments.class` 一次只接受一个类；逗号分隔时只执行第一个类。
