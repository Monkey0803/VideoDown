# P3：续播、播放设置、后台音频与画中画

> 2026-10-09 更新：当前倍速选项已扩展到最高 4×，以 `PlaybackState.kt` 为准。下文 0.5×～2×及横屏 2×描述属于 2026-09-30 当轮验收范围，不代表当前上限。后台音频、安全锁屏及正常人工解锁的新真机结果见 [P2 真机验收](p2-device-2026-10-09.md)；物理耳机拔插仍未覆盖。

本轮范围：播放进度记忆；0.5×～2×倍速与循环，视频/音频分别持久化；音频后台播放、通知、锁屏与耳机控制；视频画中画、返回保持进度、关闭释放播放。

## 实现

- `PlaybackRepository` 和纯 Kotlin 模型独立于 Android；SharedPreferences 实现独立保存音频/视频设置与文件指纹对应的进度，不改写下载历史。退出、跳转、暂停、结束和后台音频定时保存；文件更换使旧进度失效，播放完成后从头开始。
- 真实 Player 应用倍速及单曲循环；横屏倍速弹窗限高并可滚动，播放器 Activity 重建从最新进度恢复。
- `AudioPlaybackService` 拥有音频 ExoPlayer，页面只连接 MediaController；释放页面和控制器不停止后台播放。媒体会话提供标题、通知返回、系统媒体键与锁屏控制；启用音频焦点、becoming-noisy 和本地唤醒锁。打开视频会暂停后台音频。
- 音频通知目标在导航完成后被消费，防止重建时重复打开已离开的播放器。
- PiP 按实际宽高比配置，播放时 Home 自动进入，暂停时不自动进入；可显式进入。隐藏页面操作和弹窗，通过系统动作暂停/继续；展开保持原播放器。补齐 `screenLayout`，避免小窗切换重建；系统关闭仅停止 Activity 时结束该 Activity，触发播放器释放与进度保存。熄屏和锁屏排除该结束路径。

PiP 系统关闭通过系统小窗的无障碍 `ACTION_DISMISS`，不是直接 `Activity.finish()`，也不是点击系统 Close 按钮。通知测试使用真实 Notification 的媒体会话 token 和 sessionActivity PendingIntent，不宣称实际点击了通知栏按钮。系统耳机键通过 KEYCODE_HEADSETHOOK 注入，不等于物理耳机操作。

模拟器 AudioPolicy 缺少 WIRED_HEADPHONE 硬件模块，无法提供真实拔插广播。noisy 用例把事件注入正在播放的真实 Media3 接收器，保留其启用检查和暂停处理；系统分发和物理耳机拔插仍需真机确认。PiP 熄屏回归仅证明 Activity/Player 存活及 READY，不承诺自动继续播放。
