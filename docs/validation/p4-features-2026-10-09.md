### 设计取舍（与既有行为的一致性）

- **剪贴板只在窗口获得焦点后读取。** `hasPrimaryClip()` / `getPrimaryClip()` 在无输入焦点时返回 `false` / `null`，因此读取挂在 `ViewTreeObserver.OnWindowFocusChangeListener` 上，并补齐「进入时窗口已经聚焦」这一条不触发回调的路径。读取顺序为先 `hasPrimaryClip()`、再 `primaryClipDescription` 的 MIME、最后才取内容；描述检查不会触发系统提示。
- **只识别已知平台。** `ClipboardLinkPolicy` 对 `VideoPlatform.GENERIC` 一律返回 `null`，避免对浏览器地址、文件链接等任意 http(s) 文本弹出无请求的提示；`忽略` 后按链接 URL 去重，不因再次聚焦而复现。
- **确认后才解析。** 横幅只是提示，解析必须由点击触发，避免未经请求的下载；输入框已有内容、正在解析或已有结果时不打扰。
- **通知内不提供删除。** 删除不可逆且应用内要求二次确认，通知栏无法承载；独立通知只做暂停/继续。
- **独立通知随服务退出而清除。** 没有任务在传输时服务按既有设计退出（不再保活），此时保留一个控制不了任何传输的按钮会误导用户；任务完成、失败或记录消失时也会撤销对应通知。
- **REQUEST code 按槽位隔离。** `PendingIntent` 的 `filterEquals` 不含 extras，同 action 不同任务若共用 requestCode 会串任务，因此按「槽位 × 2 + 动作偏移」分配。
- **动态取色默认关闭**，保留暖橙品牌色；仅在 API 31+ 显示开关。

### 逐项证据

- **A1 剪贴板**：`ClipboardDetectDeviceTest` 在 API 37 与 API 30 均 4/4。用例写入真实剪贴板后启动 Activity，断言横幅出现、点击「解析」后链接进入输入框、`忽略` 后连续两次丢失/重获焦点不再提示、通用网页链接不提示、关闭开关后即使聚焦也不提示（重新打开后提示，证明是开关而非读取失效）。
- **A2 通知**：`TaskNotificationDeviceTest` 在 API 37 与 API 30 均通过。两路真实慢速传输（本地 FixtureServer）产生两张独立通知，逐张断言含「暂停」；随后**发送该通知自身 PendingIntent**（非手工构造 Intent）使目标任务变为 `PAUSED`，另一任务仍为 `RUNNING`/`PENDING`；暂停后的卡片变为「继续」；关闭开关后独立卡片全部撤销。同一次运行的汇总通知仍在且保留「全部暂停」。证据：`evidence/task-notification-evidence-*`。
- **A3 动态取色**：`DynamicColorDeviceTest` 在 API 37 通过，`sdk=37 brand-primary pixels=7461 dynamic-primary pixels=0 preference persisted=true`（`evidence/dynamic-color-evidence-summary.txt`）；在 API 30 走 `SDK < 31` 分支，断言开关不存在后返回。
- **A4 快捷方式**：`LauncherShortcutsDeviceTest` 在 API 37 与 API 30 均 4/4。断言三条动态快捷方式已发布，且每条的 `intent.component.packageName` 等于**当前安装包名**（debug 变体为 `com.videodown.douyin.debug` 后缀，静态 `res/xml` 快捷方式会指向未安装的包，故改为运行时发布）；分别以 `OPEN_TASKS` / `BATCH_IMPORT` action 启动并断言落地页面与弹窗；`QUICK_PARSE` 直接读取剪贴板解析且**不再出现被动横幅**。
- **A5 任务页**：`TaskListOrderTest`（JVM，8 例）覆盖状态排序、队列位置回退、标题/作者搜索、多词 AND、空结果、最新/最早/最大排序与未知大小的稳定性；`TaskSearchDeviceTest` 在 API 37 与 API 30 均通过，断言搜索框文本确实被替换、按标题与作者过滤、无结果时显示「没有符合条件的任务」、切换「最早任务」后甲在丙之上、「最新任务」后乙在丙之上。`formatEta` 由 JVM 边界用例覆盖（0/负数/停滞/不足 1 秒向上取整）。

## 未通过项与未覆盖边界

- **`P2CompletionNotificationDeviceTest` 在 API 37 模拟器上失败（超时 10 s），在 API 30 真机通过。** 该用例通过系统通知栏 UI 点击真实卡片，依赖 SystemUI。已确认与本次改动无关：临时注释掉本轮的独立通知收集器后仍以同样方式失败，而同一构建在真机通过。原始失败日志保留在 `emulator-api37/P2CompletionNotificationDeviceTest.emulator-failure.xml`，真机通过结果在 `device-api30/P2CompletionNotificationDeviceTest.xml`。本轮将其记为**模拟器环境限制**，未修改该用例。
- **`P1RecoveryNavigationDeviceTest#rateLimitedParseOpensSettingsWithoutRepeatingRequest` 是仓库既有的失效断言**（与本轮无关）：它等待文案「打造专属空间」，该文案在 `94a83b9`（优化页面布局）中已从设置页移除，而断言未同步。本轮仅把该断言改为当前实际渲染的页面标题「我的设置」，用例意图（SETTINGS 恢复动作进入设置页）不变；修复后该用例 4/4 通过。
- **动态取色的具体配色不逐像素断言。** Material You 调色板由系统根据壁纸生成，本用例只断言「品牌主色像素数在开启后发生变化」与偏好持久化，不断言系统会给出哪一套颜色。
- **独立通知的生命周期边界**：全部任务暂停后服务按既有设计退出，独立通知随之清除，因此「从通知继续一个已暂停任务」只在服务仍存活（仍有其它任务在传输）时可用；服务完全退出后的继续仍走应用内。此边界未做端到端用例。
- **API < 31 的设备无法验证动态取色渲染**（开关本身按设计不显示，API 30 真机仅覆盖该分支）。
- 剪贴板识别在 Android 12+ 首次读取他应用剪贴板时系统会弹一次访问提示，属平台行为，无法由应用消除；用例未断言该提示。
- 快捷方式未覆盖「用户手动固定到桌面」与桌面长按菜单的视觉呈现（仅断言动态快捷方式集合与 action 落地行为）。
