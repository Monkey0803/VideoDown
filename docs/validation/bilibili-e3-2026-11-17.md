# B 站应用内登录态验证（E3，2026-11-17）

## 结论

E3 已完成：设置页提供「哔哩哔哩登录」，在一个**应用内网页**里登录；登录态由系统 WebView 的
`CookieManager` 持有，以 `SESSDATA` 判断是否登录。解析时**优先用登录态**，失败后退回匿名，
两条路都要求授权时给出「重新登录」提示。只导出 B 站主机的 Cookie，不读取外部浏览器 Cookie，
也不尝试大会员/付费/权限绕过。

## 实现范围

- `data/remote/BilibiliSession.kt`（新增，纯 Kotlin）：
  - `signedIn(cookieHeader)`：Cookie 头里存在**非空** `SESSDATA` 才算登录，不缓存、不自己算过期；
  - `appliesTo(pageUrl)`：只有 B 站页面（含 `*.bilibili.com`、`b23.tv`）才附带登录态，
    Referer 单独不构成理由；
  - `cookieOrigins = [www.bilibili.com, api.bilibili.com]`，`SESSION_AUTH_FAILED = bilibili:session_auth_failed`；
  - `preferSession(signedIn)` 固化「有登录态先试」的顺序。
- `data/generic/BrowserSessionStore.kt`：`extractorCookieUrls` 对 B 站页面追加两个 Cookie 来源；
  新增 `bilibiliSignedIn()`，与 X 一样每次现查 CookieManager。
- `presentation/login/XLoginScreen.kt`：网页登录容器参数化标题与说明（X 保持默认值），
  B 站复用同一套 WebView/状态检测/清理逻辑。
- `presentation/settings/SettingsScreen.kt`：账号页新增「哔哩哔哩登录」行，显示已登录/未登录/检查中，
  点击打开登录页；「清除网页登录态」清完后同时刷新两个站点的状态。
- `data/repository/MultiPlatformVideoRepository.kt`：`parseBilibili` 先试登录态；
  登录态失败且为授权类错误时退回匿名；匿名也要求授权时返回
  `bilibili:session_auth_failed`（`LOGIN_REQUIRED`）；其它失败照常上报，不多跑一次匿名。
- 新增文案（中英）：登录标题/提示、设置行与状态、说明、`bilibili_session_auth_failed` 错误。

## 未覆盖边界

1. **真实账号登录未自动化**：设备用例直接写入 `SESSDATA`，没有在测试里输入账号密码；
   真实登录、账号风控与验证码需要在真机上人工验证一次。
2. **登录态带来的画质差异未实测**：有登录态时 B 站通常提供更高画质，本轮没有构造
   「同一视频匿名 720P、登录 1080P」的对照，也不验证大会员内容。
3. **只访问账号在正常网页中能播放的内容**是代码约束（不注入会员参数、不绕过付费），
   没有对真实付费/地区限制内容做否定性验证。
4. `SESSDATA` 过期由 B 站决定，应用不做主动探测；只在解析失败时提示重新登录。
5. 多 P 合集与真实 `b23.tv` 展开仍缺真实链接验证；平板/折叠屏、API 26/28 未验证。
